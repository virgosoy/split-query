# 13: 更新提示 UI（圆点、面板、检查与应用）

**What to build:** 顶栏加入更新入口与圆点，点开模态面板显示当前版本与检查状态；启动/回前台自动检查（10 分钟节流、离线跳过），面板打开即手动检查；点「立即更新」让 `waiting` SW 接管并重载。包含 WebKit 兜底与真机验收。

**Blocked by:** 12

**Status:** open

- [ ] 顶栏紧凑圆形图标（aria-label「检查更新」），仅 PROD 渲染；存在 `waiting` 时显示圆点，更新完成后圆点消失
- [ ] 面板显示当前版本（读 `dist/index.html` 的 meta；dev 不渲染入口）、状态行与主按钮：主按钮在「检查更新 / 检查中… / 立即更新 / 更新中…」间切换；状态行显示「已是最新 / 发现新版本 / 当前离线，无法检查 / 检查失败，请稍后再试 / 更新正在下载，请稍后再试」
- [ ] 打开面板：已有 `waiting` → 直接显示「立即更新」；否则在线时自动检查；离线显示「当前离线，无法检查」
- [ ] 启动时与 `visibilitychange` 回到前台时自动检查；10 分钟内只自动查一次；离线跳过；手动检查不受节流限制
- [ ] 「立即更新」先确认 `registration.waiting`；没有则提示稍后再试且不重载；有则 `SKIP_WAITING` → `controllerchange` → reload；5 秒兜底重载
- [ ] 兜底生效：`update()` 15 秒超时；等安装 30 秒；`installed` 后等 `waiting` 2 秒；25ms 轮询；`update()` resolve 后让出宏任务等 `updatefound`
- [ ] 更新不触碰 IndexedDB；不保留搜索词与滚动位置；不做二次确认、「稍后/忽略」、清除缓存或重置
- [ ] 人工验收：部署 v1 → 做一次真实应用改动部署 v2 → 回到前台看到圆点 → 立即更新 → 面板版本变化；iPhone 14 / iOS 16.1.1 真机再走一遍
- [ ] `npm run check` 与 `npm run smoke` 通过（本票不新增纯 seam；smoke 不因 UI 改动而放宽）

## 备注

- 更新状态机是薄胶水，按项目政策人工验证；自动化只覆盖票 12 的 SW 不变量与离线承诺。
- 「发现新版本」不显示新版本号；要显示需给 waiting SW 增加版本回报协议，本票不做。
- 面板复用现有 `.usage` 模态浮层样式，避免第二套弹层。
