# 08: 资源空间面板

**What to build:** 顶栏一个独立按钮点开**模态浮层**，显示本应用在手机上实际占用的存储：`条目数据`（本地条目副本的实测净字节）、`应用资源`（离线缓存的页面骨架/脚本/样式/图标/manifest 的实测字节），以及两者的一行 `合计`。从未导入过时 `条目数据` 显示「尚未导入」；某个桶读不到时该行显示「不可用」且**不显示合计**。v1 只读。

**Blocked by:** None（可立即开始）

**Status:** ready-for-agent

- [ ] 新增纯 seam `format.ts`：字节 → 人类可读（KB/MB，一位小数，**不加"约"**），配自动化测试覆盖边界（0、不足 1 KB、1023 / 1024 进位、多位小数）。`CLAUDE.md` 已声明"三个纯 seam"，本票补上第三个的实现与测试
- [ ] 顶栏独立按钮 → 模态浮层，可关闭（关闭按钮 + 点遮罩）
- [ ] `条目数据`：打开面板时**从 IndexedDB 现读**条目，按 UTF-8 内容净字节求和（**不含** JSON 结构开销，使其可与用户的文件大小直接对照）
- [ ] `应用资源`：遍历**所有** cache 求和响应字节（**不硬编码缓存名**，避免与 service worker 里的常量重复声明）
- [ ] 一行 `合计`（两个实测值之和），并标注口径：仅本站点占用，不含浏览器 HTTP 缓存与系统快照，≠ 手机剩余空间变化
- [ ] 从未导入 → `条目数据` 显示「尚未导入」（**不是** `0 字节`）；单桶读取失败 → 该行「不可用」且**合计整行不显示**（缺一项时合计是编造，不是求和）
- [ ] 面板附一句恢复说明：文件是唯一真源，重新导入整体替换、**不累积**
- [ ] 手工验证：`npm run check` 通过；面板在 `npm run build` + 预览（或线上）下数值正确 —— **dev 下无 Service Worker，`应用资源` 自然测不出，这是预期而非缺陷**
- [ ] 不引入 `navigator.storage.estimate()` 探测分支，不引入 `navigator.storage.persist()`（理由见 spec 的 Out of Scope）
