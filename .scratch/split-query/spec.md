# Split-Query 规格

## Problem Statement

用户维护一个按空行切分的文本书签文件：每条目第一行为空格分隔的「关键词行」，其余「其他行」多为 URL、有时为说明文字（条目甚至只有 1~2 行）。用户希望有一款**无服务器、离线可用**的 PWA，在 iPhone 上按一套自定义搜索语法快速检索这些条目，并把链接交给系统浏览器打开。

## Solution

一个部署在 GitHub Pages 的离线 PWA（Vanilla TypeScript + Vite，无运行时框架）：

- **数据**：运行时从 iOS「文件」App（含 iCloud）导入用户的 UTF-8 文本文件；解析后存 IndexedDB；**文件是唯一真源**，重新导入整体替换（见 ADR-0001）。
- **查询**：多行编辑搜索框 — 同行空格＝**AND**、行间＝**OR**；每个条件单元自包含「字段＋模式＋词」。
- **快捷输入**：候选词自动补全（含字段前缀之后；`h:` 系列用首词词库，见「v1.1 追加（2026-11-26）：自动补全字段前缀」）、算子按钮插入/取反（含 `k^:` / `k$:` / `k^$:` 锚点）、最近搜索粘贴回编辑框。
- **展示**：命中条目整体完整显示；URL 行点击在系统浏览器打开；结果默认保持导入文件顺序（不做相关度排序），可按需切换为文件倒序或一次性随机排列。

## User Stories

1. 用户想在 iPhone 上直接选择自己的文本文件导入，以便离线查看全部条目。
2. 用户想导入后立即看到解析出的条目列表（整条目完整显示），以便确认导入正确。
3. 用户想点条目里的链接在系统浏览器打开，以便跳转到对应网页。
4. 用户在搜索框输入多个词（同行）按 AND 检索，以便只看到同时命中的条目。
5. 用户在不同行输入不同词按 OR 检索，以便一个查询覆盖多个主题。
6. 用户想让某一行只在关键词行里匹配（`k:`），以便按关键词而非链接文本检索。
7. 用户想按首词精确/开头/结尾匹配（`h:`/`h^:`/`h$:`/`h^$:`），以便定位类目/组名条目。
8. 用户想排除含某词的条目（`!:词`），以便过滤不想要的主题。
9. 用户希望算子大小写、半全角冒号都能识别，以便用中文键盘也不易打错。
10. 用户想输入时看到从关键词行汇总的候选词点选补全，以便减少打字。
11. 用户想用按钮插入/修改各算子前缀，以便不手动打符号。
12. 用户想看最近搜索并能粘贴回编辑框再调整，以便复用查询。
13. 用户想空查询显示全部条目，以便总览。
14. 用户想结果默认保持导入文件顺序，以便位置可预期；需要时再临时随机排列。
15. 用户想重新导入时整体替换并看到条目数，以便更新内容。
16. 用户想刷新页面后数据仍在，以便离线使用。
17. 用户想把应用装到主屏离线使用，以便不联网也能检索。

## Implementation Decisions

- **架构**：无服务器纯静态 PWA；数据本地优先、运行时导入（ADR-0001）；应用不内嵌网页，链接一律交系统浏览器。
- **数据流**：文件（运行时导入）→ 解析为条目（parse seam）→（可选：查询谓词过滤，entry seam）→ 渲染为条目卡片。
- **测试 seam（均为纯函数，v1 的自动化测试边界；v1.1 追加 format / order / search-text）**：
  - **parse seam**：`文本 → 条目[]`。捕获空行切分、关键词行/首词/其他行划分、URL 识别、空白边界。
  - **query seam**：`搜索文本 → (条目)=>boolean`。捕获全部语法矩阵、大小写与半全角冒号归一、文件顺序保持（谓词不改变顺序）。
- UI 与 IndexedDB 为薄胶水，v1 不设自动化 seam（本地起 Vite 人工验证）。
- **存储**：IndexedDB 单集合；每次导入整体替换。
- **快捷输入词库**：全部条目关键词行出现过的词，去重、按出现次数降序；`h:` 系列另用首词词库（见「v1.1 追加（2026-11-26）：自动补全字段前缀」）。
- **排序**：默认保持导入文件顺序；可按需切换为文件倒序（见「v1.1 追加（2026-11-25）：文件倒序」）或一次性随机排列（见「v1.1 追加（2026-11-22）：按需随机排序」）。
- **命名**：无关词典术语遵循 `GLOSSARY.md`。

## Testing Decisions

- 测试只经公开纯 seam（parse / query / format / order / search-text），不触碰内部实现；断言值来自**独立来源**（已知好值、规格语法矩阵字面量），避免与实现同算式。
- **parse seam**：已知文本 → 精确的条目结构断言。
- **query seam**：一张**语法矩阵表**驱动的参数化用例：对每条算子/组合给定「查询 + 命中/不命中条目」。
- 不使用 fake-indexeddb / jsdom（薄胶水人工验）。
- 运行器 vitest；本地全量通过后再进入下一票。

## Out of Scope

- v1 不做条目增删改（只读 + 搜索）。
- 不做多文件/文件夹管理（单文件）。
- 不做相关度排序、短语（`"…"`）算子。
- 不做应用内嵌浏览器；不做账号/同步/服务端。

## Further Notes

- **查询语法（完整）**：

| 输入 | 语义 |
| --- | --- |
| `词` | 全文包含词（默认） |
| `k:词` | 关键词行包含词 |
| `k^:词` / `k$:词` / `k^$:词` | 关键词行 开头 / 结尾 / 精确 |
| `h:词` | 首词包含词 |
| `h^:词` / `h$:词` / `h^$:词` | 首词 开头 / 结尾 / 精确 |
| `!…`（`!react`、`!k:react`） | 对任意条件取反 |

- 规则：行内空格=AND、行间=OR；子串匹配、拉丁词大小写不敏感；算子大小写不敏感、半角 `:` 与全角 `：` 等价；`!` 须紧接算子或词。
- 术语见根目录 `GLOSSARY.md`；架构决定见 `docs/adr/0001`。

## v1.1 追加（2026-11-21）：资源空间面板

### User Story（追加）

18. 用户想知道本应用在手机上实际占了多少存储（条目数据 / 应用资源 / 合计），以便在手机存储紧张时判断这个应用值不值得留。

### Implementation Decisions（追加）

- **只有两个存储桶**：`条目数据`（IndexedDB 中的条目本地副本）与 `应用资源`（离线所需的页面骨架、脚本、样式、图标、manifest，即缓存中的内容）。**应用本体与缓存是同一个桶**，没有第三个桶；除「地址前缀替换」开关的 `localStorage` 偏好外，这个应用不使用其他浏览器存储，该偏好不计入面板（2026-11-25 决定：不做补统计；理由见 `draft.md`）。
- **入口**：顶栏独立按钮 → 模态浮层（可关闭）。v1 **只读**，不含清理 / 导出 / 系统设置引导。
- **口径**：数值为**实测字节**，格式化为人类可读（KB/MB，一位小数，**不加"约"**——数是被量出来的，不是估算的）；每次打开面板现读现算。`条目数据` 报条目的 **UTF-8 内容净字节**（可与用户的文件大小直接对照），不含 JSON 结构开销。
- **合计**：两个实测值之和，并标注口径限制：仅本站点占用，不含系统缓存，≠ 手机剩余空间变化。
- **降级**：从未导入 → `条目数据` 显示「尚未导入」而不是 0（0 会被读成"有数据但很小"）；单个桶读取失败 → 该行显示「不可用」，并**隐藏整行合计**（缺一项时合计就不再是求和，而是编造）。
- **新纯 seam**：`src/lib/format.ts`（字节 → 人类可读）纳入自动化测试；`CLAUDE.md` 的纯 seam 数量由二改三。
- **首用提示（独立票）**：空态文案补一句主屏使用建议——离线可用，且数据不受 Safari 的 7 天清理限制。事实来自 WebKit 官方说明（主屏 web app 不属于 Safari、有自己的使用天数计数、不受 7 天 script-writable storage 清理影响），因此**无条件陈述、不做任何检测**。

### Out of Scope（追加）

- **不用 `navigator.storage.estimate()` 读「已用 / 配额」**：该 API 落在 Safari 17 / iOS 17，目标设备 iOS 16.1 上**不存在**（同一版本的 `StorageEstimate.usageDetails`、`storageBuckets` 在 Safari 里从未有过）。目标设备短期内不升级，写探测分支等于一段永远不渲染、因而无法人工验证的 UI。将来升级到 iOS 17 后可作为新票追加。
- **不引入 `navigator.storage.persist()`**：该 API 在 iOS 16.1 上带 bug（WebKit 于 Safari 17 周期才修复），且主屏豁免已使 7 天清理不适用于本应用的主用法。
- 不做清理 / 导出 / 系统设置引导（见 `draft.md` 的后续清单）。

## v1.1 追加（2026-11-21）：搜索框字号契约

### Implementation Decisions（追加）

- **搜索输入框字号固定 `16px`**：iOS Safari 聚焦计算字号 `< 16px` 的 `input`/`textarea` 时会强制放大页面（15.99px 也触发）；放大后内容宽于视觉视口、可横向拖动，妨碍查看结果。因此 `.search` 的 `font-size: 16px` 是**构建契约，不得下调**。修复一律走字号，不用 `maximum-scale` / `user-scalable=no`（会禁掉用户双指缩放，且 iOS 10+ 对该类声明处理不稳定），不用 JS focus 补丁。

## v1.1 追加（2026-11-22）：更新提示与手动更新

### User Story（追加）

19. 用户想在应用有新版本时看到不打断当前操作的提示，并能一次点击完成更新，以便主屏 PWA 不被长期困在旧版。
20. 用户想随时手动检查更新，并在没有新版本、离线或检查失败时得到明确回答，以便确认自己用的是不是最新版。

### Implementation Decisions（追加）

- **检测与生效（prompt 模式）**：构建生成 `dist/sw.js`，注入版本 `v<package.version>+<短 commit SHA>` 与完整预缓存清单（`./`、`index.html`、全部哈希 JS/CSS、图标、manifest，构建时去重）。install **不**无条件 `skipWaiting`；新 Service Worker 停在 `waiting`，`waiting` 是「有更新」的**唯一**依据。应用更新 = `SKIP_WAITING` → `skipWaiting` → `controllerchange` → reload（5 秒兜底）。activate 按版本名清理旧 `split-query-*` 缓存并 `clients.claim()`；导航仍网络优先、静态资源仍缓存优先。
- **全量预缓存取代 warmup**：等待中的新版本自带完整离线资源，即使所有客户端关闭后自动接管，离线冷启动仍可用；删除 `sw.js` 的 warmup 消息处理器与 `main.ts` 的预热代码。票 10 的逐条容错与 draft 的「预热 URL 去重」条目随之作废（票 12 关闭时已标注作废）。
- **检查时机**：启动一次；每次回到前台（`visibilitychange`）一次；10 分钟内只自动查一次；离线跳过。手动检查（打开更新面板）不受节流限制。自动检查失败静默；手动检查明确显示「当前离线，无法检查」或「检查失败，请稍后再试」。
- **UI**：顶栏紧凑圆形图标（aria-label「检查更新」），存在 `waiting` 时显示圆点；点开复用模态浮层，显示**当前版本**、状态行与主按钮。主按钮在「检查更新 / 检查中… / 立即更新 / 更新中…」间切换；状态行显示「已是最新 / 发现新版本 / 当前离线，无法检查 / 检查失败，请稍后再试 / 更新正在下载，请稍后再试」。点「立即更新」直接更新并重载，不二次确认，不保留搜索词与滚动位置。不显示新版本号、不做「稍后/忽略」、不做清除缓存或重置；dev 下不渲染更新入口。
- **版本来源**：`v<package.version>+<短 commit SHA>`。`npm run build` 在 `vite build` 后运行 `scripts/build-sw.mjs`：扫描 `dist/`、把 `dist/index.html` 的版本占位替换为真实版本、由 `scripts/sw.template.js` 生成 `dist/sw.js`。dev 下版本显示 `dev`。
- **部署**：GitHub Actions 加 `paths:` 白名单（`src/**`、`public/**`、`index.html`、`vite.config.ts`、`package.json`、`package-lock.json`、`tsconfig.json`、`scripts/**`、workflow 自身），docs / 票提交不再触发部署，避免假更新提示。
- **可靠性兜底**：`registration.update()` 15 秒超时；等新 Service Worker 安装 30 秒；`installed` 后等 `waiting` 2 秒；25ms 轮询；部分 WebKit 先 resolve `update()` 再派发 `updatefound`，故让出一个宏任务；`controllerchange` 5 秒兜底重载；离线跳过自动检查。
- **测试**：不新增纯 seam。`npm run smoke` 继续验证离线承诺，并新增 `dist/sw.js` 不变量（版本注入、完整预缓存清单、`SKIP_WAITING` 处理器、无无条件 `skipWaiting`）；更新流程人工验收（含 iPhone 14 / iOS 16.1.1 真机）。

### Out of Scope（追加）

- 不用 `version.json` 或轮询版本文件判断更新：`waiting` Service Worker 是唯一依据。
- 不做自动静默更新、离线就绪横幅、「稍后/忽略」、清除缓存 / 重置应用。
- 不新增第二条自动化更新流 smoke（可作为后续票）。

## v1.1 追加（2026-11-22）：按需随机排序

### User Story（追加）

21. 用户想按需把当前结果随机排序，以便从久未查看的条目里重新发现内容。
22. 用户想在随机模式下随时再换一批，以便得到新的随机顺序。

### Implementation Decisions（追加）

- **默认与开启**：默认始终是导入文件顺序。随机是结果区排序行里的**可选项**，不是启动即随机；开启后作用于当前显示的全部条目（空查询＝全部条目，搜索时＝命中结果）。它只改变渲染顺序，不改变命中集合，也不修改条目数据。
- **排列单位**：全局完全混排，所有条目都参与（包括无链接条目）；不保留首词/类目相邻。
- **稳定性**：每次从「文件顺序」切到「随机」，为全部条目滚出一个新排列；「换一批」重滚一次。停留在随机模式时，输入搜索、增删条件、清空查询都**不重滚**——结果只是该全排列的子序列，先后稳定。
- **入口**：结果区上方单独一行，左侧「排序」标签 + 原生下拉（`文件顺序` / `随机`），右侧「换一批」；「换一批」只在选中「随机」时出现。下拉与按钮字号按 `16px` 处理（iOS Safari 对聚焦时字号 `<16px` 的 `select` 同样会放大页面）。没有条目时整行隐藏。
- **生命周期**：随机选择只在当前会话内有效；刷新或重新打开回到 `文件顺序`，不写 `localStorage`。重新导入文件时保持当前排序选择：选「文件顺序」展示新文件顺序；选「随机」则为新数据滚一个新排列。
- **新纯 seam**：`src/lib/order.ts` 的 `shuffle<T>(items, random)`（Fisher–Yates，不修改入参，随机源注入）纳入自动化测试；`CLAUDE.md` 的纯 seam 数量由三改四。query seam 及其测试不变。
- **重滚入口**：原生 `<select>` 再次选中已选中项不会触发 `change`，所以重滚只能由「换一批」按钮承担，不依赖下拉。

### Out of Scope（追加）

- 不做相关度排序、不做「随机抽一条并打开」、不做按首词类目分组随机。
- 不把随机选择或随机排列持久化到 `localStorage` / IndexedDB。
- 不为随机排序改变搜索结果或最近搜索的行为。

## v1.1 追加（2026-11-23）：关键词锚点快捷按钮

### User Story（追加）

23. 用户想用按钮给关键词行条件加开头 / 结尾 / 精确锚点，以便不手打 `^` / `$`。

### Implementation Decisions（追加）

- **按钮集合**：工具栏按字段分组为 `关键词 | 关键词^ | 关键词$ | 关键词^$ | 首词 | 首词^ | 首词$ | 首词^$ | 排除!`；字段按钮「关键词行」改名为「关键词」，「首词精确」改为符号式「首词^$」。
- **行为**：沿用预设按钮模型——作用于当前编辑行最后一个词，加/替换字段算子前缀；空行插入前缀等待输入；保留 `!` 取反。例如 `h:vue` 按「关键词^」得到 `k^:vue`。
- **移除**：行级「仅关键词行」按钮与批量改写功能；`k:` 语法本身保留，仍可手打或点「关键词」。
- **文案**：占位符同步为「k: 关键词 / h: 首词 / ^ $ ^$ / ! 排除」。
- **测试**：query seam 与语法矩阵不变；本票是薄 UI 胶水，按 `CLAUDE.md` 人工验证。

### Out of Scope（追加）

- 不让自动补全在字段前缀后继续工作（`k:` / `k^:` 等之后仍隐藏候选）；该缺口记在 `draft.md`。

## v1.1 追加（2026-11-24）：搜索文本编辑 seam

### Implementation Decisions（追加）

- **行为不变的重构**：把 `main.ts` 里的当前行读取/改写、算子 inventory（`FIELD_OPS`）与补全过滤抽成纯 seam `src/lib/search-text.ts`（`editSearchText`、`completions`）；`main.ts` 只保留 DOM wiring，focus/render 时机不变。

- **唯一已知行为收紧**：非法锚点顺序（如 `k$^:`）不再被工具栏当作字段前缀，而是按裸词处理；与 query 的合法语法一致，用测试固定。
- **测试边界**：新增 `src/lib/search-text.test.ts` 并补 `query.test.ts` 的 `splitToken` 用例；`CLAUDE.md` 的纯 seam 数量由四改五。不新增 ADR，不新增 GLOSSARY 术语。

### Out of Scope（追加）

- 仍不做字段前缀后的自动补全（记在 `draft.md` 的后续项）。
- 不改搜索语法、算子集合或 UI 标签。

## v1.1 追加（2026-11-25）：地址前缀替换

### User Story（追加）

24. 用户想让同一服务的多个基址可以互相替换打开，以便用当前网络可达的基址访问同一条链接。

### Implementation Decisions（追加）

- **地址条目**：首词**严格等于**「地址」的条目（`地址 内网` 也算；`地址栏` 不算）。其其他行中的每个 http(s) 行提供一个基址。
- **基址与匹配**：基址 = `scheme://host[:port]/`；路径、查询、哈希都忽略。scheme 与 host 大小写不敏感，端口严格一致（不做默认端口归一）；无尾斜杠按有尾斜杠处理；只差路径的地址行按同一基址去重。只认 http(s)。
- **作用域**：非地址条目的链接命中某个基址时，替代项只取**同一条目内其他 URL 行**的基址；多个地址条目含同一基址时取它们「其他行」的并集并按基址去重。地址条目自己的链接不显示替代项。
- **替换**：替代 URL = 替代基址 + 原链接基址之后的路径/查询/哈希（原样保留）。
- **入口**：结果区上方（排序行下方）单独一行紧凑开关「地址前缀替换」，`role="switch"`，默认开。仅当**全部条目中至少有一条非地址条目的链接能获得 ≥1 个替代**时出现；关闭时该行保留、替代项消失。
- **偏好**：开关状态存 `localStorage`（key `split-query:address-alternatives`；键不存在视为开，只在关闭时写 `off`）。同步读取，刷新后保留；重新导入不改变。
- **渲染**：命中的链接下方一行「换前缀」+ 替代 chip；最多 2 个，其余收成「还有 N 个」。chip 是 `<a target="_blank" rel="noopener noreferrer">`，文本为替代基址去掉尾斜杠，`title`/`aria-label` 给出完整替换后 URL。点「还有 N 个」原地展开、按钮消失、不可收起；任何重渲染回到折叠态。
- **新纯 seam**：`src/lib/address.ts`（`isAddressItem`、`buildAddressPool`、`alternativesFor`）纳入自动化测试；`CLAUDE.md` 的纯 seam 数量由五改六。
- **面板口径**：`spec.md` 的「只有两个存储桶」段落补注——除该开关的 `localStorage` 偏好外不使用其他浏览器存储，且面板不统计它；`main.ts` 的面板注释同步。

### Out of Scope（追加）

- 不做替代基址的全局并集（不同地址条目的基址不互相串用）。
- 不扩大地址条目的判定（不改首词规则、不做别名）。
- 不自动探测基址可达性；替代项不排序（按文件顺序）。
- 资源空间面板统计 `localStorage` 偏好：**不做**（2026-11-25 决定；上限 35 B、默认 0 B，为它新增第三个桶不划算，理由见 `draft.md`）。

## v1.1 追加（2026-11-25）：URL 行描述

### User Story（追加）

25. 用户想在 URL 行里写一句说明，并让它不被当成 URL 的一部分，以便链接仍能正常打开、地址条目仍能参与换基址。

### Implementation Decisions（追加）

- **切分规则**：只有以 `http(s)://` 开头的其他行参与；URL = 第一个空白串之前，描述 = 其后并去掉首尾空白；无空白则描述为空；内部空白保留。空白口径为 JS `\s`（半角空格、Tab、全角空格、NBSP）。
- **数据形状**：`parseFile` 与 `otherLines` 不变，IndexedDB 无迁移；parse seam 新增纯函数 `splitUrlLine(line): { url, note } | null`（非 http(s) → null，无描述时 `note` 为 `''`），`main.ts` 渲染与 `address.ts` 取基址共用。
- **渲染**：URL 行统一为 `.link-row`（链接 + 可选 `.link-note`）；链接文字与 `href` 都只含 URL；描述为静音 13px、可折行；「换前缀」chips 行接在 `.link-row` 之后。
- **搜索**：描述仍是条目文本的一部分，参与全文搜索，行为不变。
- **换基址**：地址条目的 URL 行同样切分；基址只取 URL 部分，描述不影响前缀匹配，地址条目自己的描述照常显示。
- **测试**：扩展 `parse.test.ts` 与 `address.test.ts`；不新增 seam，`CLAUDE.md` 的六条清单不变。

### Out of Scope（追加）

- 不支持未编码的空格 URL（URL 内含空格必须写成 `%20`）。
- 不改关键词行的分词规则；不把描述提升为独立字段，也不参与排序或换基址。

## v1.1 追加（2026-11-25）：文件倒序

### User Story（追加）

26. 用户想把文件里的条目按相反顺序查看（最后一条在前），以便优先看到最近追加的内容。

### Implementation Decisions（追加）

- 不做「随机倒序」或把倒序与随机叠加。
- 不反转条目内部的行顺序。

## v1.1 追加（2026-11-26）：自动补全字段前缀

**Status:** resolved（2026-11-27；iPhone 真机验收待做）

### Problem Statement（追加）

用户已经能用按钮或手打得到 `k:`、`h:`、`k^:` 等字段算子前缀，但前缀一旦出现，候选词就整排消失——最需要候选的时刻（刚点完算子按钮、准备输入值）反而只能手打。更糟的是，现有候选词库汇总了关键词行的全部词，而 `h:` 只匹配首词；一旦允许 `h:` 后补全，就会列出点了必然零结果的候选。

### Solution（追加）

自动补全改为按「值」工作：末词的 `!` 与字段前缀不再屏蔽候选，点选只替换值并原样保留前缀与 `!`；`h:` 系列改用首词词库，裸词与 `k:` 系列沿用关键词行词库；值为空时也立即给出对应词表的前 8 个候选。

### User Story（追加）

27. 用户想在打出 `k:` / `k^:` 等字段前缀后仍看到候选词，以便不用手打值。
28. 用户想点选候选后只替换值、保留已写好的前缀与锚点，以便继续微调条件。
29. 用户想用大写 `K:`、全角冒号 `k：` 或带 `!` 的前缀时也能补全，且点选后前缀原样不动，以便中文键盘输入不被规范化。
30. 用户想在 `h:` 系列之后只看到首词候选，以便避免点选必然零结果的词。
31. 用户想在值还空着（刚点完算子按钮）时就看到候选，以便「按钮 → 选词」两步完成输入。
32. 用户想在裸词（无前缀）时继续看到关键词行候选，以便保持现有输入习惯。
33. 用户想在多行 OR 输入中只对最后一行末词补全，以便既有编辑模型不变。
34. 用户想在 `!` 排除词上也能补全，且点选后 `!` 仍在，以便用候选写排除条件。
35. 用户想候选仍只来自关键词行/首词、不混入 URL 与链接描述，以便候选列表保持可信。

### Implementation Decisions（追加）

- **补全键**：候选匹配对象是末词去掉 `!` 与字段算子前缀后的值（`splitToken` 的 `value`）；`negate` 与 `prefix` 都不再使候选为空。空文本（无 token）仍无候选；值为空（`k:`、`h:`、`!` 等）视为空前缀匹配，取对应词表前 8。
- **点选改写**：只替换值，token 重建为 `!` + 原前缀 + 候选词；前缀逐字保留（大小写、半/全角冒号、锚点原样），不做规范化。chip 文案仍为裸词。
- **词库分工**：裸词与 `k:` 系列用关键词行词库（现状）；`h:` 系列用首词词库——对每个条目的 `headKeyword` 做同样的词频聚合。两份词库同规则：词频降序、同频首见顺序、去重、大小写不敏感匹配、排除与输入完全相等、上限 8；URL 行与链接描述不参与。
- **字段判定**：在 search-text seam 内按 `splitToken` 的前缀首字母选表（`k` → 关键词行词库，`h` → 首词词库，无前缀 → 关键词行词库）；`main.ts` 只构建并传入两份词表，不做字段判断。
- **query seam**：新增 `buildHeadVocabulary(items)`，与 `buildVocabulary` 共享私有聚合 helper；现有 `buildVocabulary` 的签名与行为不变；不新增 seam，`CLAUDE.md` 的六条清单不变。
- **UI**：候选 chip 的渲染、点击、focus、隐藏时机不变；唯一变化是出现条件与点击结果。触发时机仍随 `renderFiltered()`。
- **不变量**：只处理最后一行最后一个 token；多行 OR、搜索语法与匹配语义、排序、存储、Service Worker 均不变。

### Testing Decisions（追加）

- **search-text seam（最高 seam）**：`completions` 与 `editSearchText({kind:'complete'})` 的矩阵测试扩展：裸词 / `k:` / `k^:` / `h:` / `!` / `!k:` / 全角冒号 / 大写前缀 / 值为空 / 多 token / 多行；断言只经公开函数看文本输出与候选列表，不触碰 DOM。现有「字段前缀后不补全」用例翻转为新契约。
- **query seam**：`buildHeadVocabulary` 的参数化测试——聚合首词、词频降序、同频首见、去重、空条目集合；复用 `buildVocabulary` 的测试风格。
- **UI 胶水**：扩展 `scripts/verify-quick-input.mjs`，断言候选 chip 在各前缀状态下出现/隐藏、点选后的文本，以及 `h:` 只出现首词候选；fixture 沿用现有 3 条目（已含多词关键词行，足以区分两份词库）。
- 不新增 fake-indexeddb / jsdom；不新增 seam。

### Out of Scope（追加）

- 光标感知补全：仍固定作用于末行末词，不看光标/选区（2026-11-26 记入 `draft.md` 后续项）。
- 不改变候选词库来源（仍只有关键词行/首词，不纳入 URL 行、链接描述或其他行文本）。
- 不按命中结果动态过滤候选、不做模糊匹配 / 拼音 / 权重学习。
- 不改搜索语法、算子集合、工具栏按钮、最近搜索、排序与存储。
- 不把候选词库扩展到「全文词」，也不为裸词区分首词/关键词之外的词源。
